## 1. 原因: 事実照合が「キューに積むとき」に1回しか走っていなかった（`d62d42b`）

承認経路の検査は**文字数とURLだけ**だった。そのため次の2つが無検査で外に出ていた。

1. 古いコードが作り、キューに残っていた文面
2. 承認画面で人が書き換えた文面

今回の文面は現行の生成コードからは出ない（接頭辞を【発売情報】に強制し、
絵文字は投稿不可にしている）。8/31 に本人が「古いコードによる残留品」として
報告していた PARM の項目が、数日後に承認されて出た、と見るのが最も整合する。

### 私の誤りの核心

「事実照合を通ったものだけ自動投稿、引っかかったら承認待ち」と設計し、
**承認待ちを"安全な側"として説明していた。** 実際には承認経路こそ検査が最も薄かった。
自動投稿の門は何重にも固めながら、人が通る門を開けたままにしていた。

### 直し方

`verifyFinalText()` — 投稿の直前に、**出す文そのもの**を原文と突き合わせる。判定の芯は1つ:

> 投稿文に出てくる金額と日付は、すべて原文にも存在しなければならない

生成側がどう間違えても、原文に無い数字は外に出せない。

- 形式違反（絵文字・URL・ハッシュタグ・超過）→ 400 で拒否
- 原文で裏が取れない数字 → 何が確認できないかを名指しして 409 で確認
- 原文が保存されていない古い項目 → 「裏取りできない」と明示して確認
- 「発売中」と、まだ来ていない発売日は両立しないことも見る

実際に出た文面で4件すべて検出。正しい文面（9/7・630円税別・全国）は素通り。

### まだ止まらないもの

味・原材料の説明文は数字ではないので、この検査では止まらない。
「加賀棒ほうじ茶を使用」のような記述の真偽は依然として人が読むしかない。

## 2. 日付比較のバグ（`2293781`）— 本人側のレビューで発見

`d62d42b` に入れた判定で、原文の日付 `"9-7"` と today `"2026-09-03"` を
文字列比較していた。`"9..." > "2..."` は常に真なので、原文のすべての日付が
未来扱いになり、発売済みでも「発売中」と書くたびに確認を求められる。

安全側の誤動作だが、**狼少年になった検査は無い検査より悪い。**
今回の事故は「承認を1タップで押せた」ことが一因なので、確認の重みを下げる
バグは事故の再発に直結する。

- 今日を基準に年を補って実時刻へ解決（半年以上ずれたら隣の年）
- 「9月上旬」のような曖昧な値は比較の対象から外す

## 3. 投稿文にURLを入れない（`f4cf24d`）

> Xのアルゴリズムは、URLリンクがあると伸びない

出店・イベント・コラボ／あいぱく関連は「見出し＋URL」を積んでいた。見出しだけに変更。
記事へは承認画面のリンクから飛べる。キューに残る古い項目も画面読み込み時にURLを落とす。

副産物: 投稿前の照合はURLを拒否するため、これまで承認のたびに手でURLを消す
往復が発生していた。それも無くなった。

## 4. 承認ボタンが「無反応」に見えた（`54532c7` → `dd1e950`）

> クーリッシュの巨峰、承認しても投稿されないんだけど？

サーバーは絵文字（🍇🍇🍇✨）で 400 を返していた。**エラーは画面上部の1行にしか
出ず、スマホでボタン付近を見ているときには視界に入らない。**

- 文字数表示の隣に「絵文字が4個（上限2個）」を常時表示。押す前に気づける
- 拒否されたときは alert でも出す

### 根っこは設計の食い違い

| 仕組み | 言っていること |
| --- | --- |
| 生成プロンプト | 絵文字は使わない |
| 文体の見本の自動更新 | 実投稿を見本にする → 実投稿は絵文字を使う |
| 投稿前の検証 | 絵文字は投稿不可 |

**本人の文体を学ばせる仕組みが、投稿できない文面を作らせていた。**
「絵文字禁止」は初期に私が勝手に決めたルールで、本人の希望ではなかった。

本人の判断で「最大2個まで許可」。生成プロンプトと検証を**同時に**揃えた。

> 教訓: 生成のルールと検証のルールは、必ず同時に直すこと。
> 片方だけ変えると「作れるが出せない」文面が生まれ、承認画面が無反応に見える形で表面化する。

### 私の説明ミス

「末尾に🍇1個なら通る」と案内したが、2個許可はまだ本番に入っていなかった。
手元のコードと本番を混同した。スマホから push できない状況で、
本人を2回足止めした。

## 5. 投稿先と画像の選択（`9b74b73`）

> X投稿もインスタのように画像を選べるようにしたい。Xのみ／インスタのみ／両方を選べるようにしたい

- 投稿先: X のみ／Instagram のみ／両方（既定 X のみ）
- 投稿画像: 画像なし／候補から選ぶ／アップロード（既定プレス画像）。X と IG で同じ画像
- IG は画像必須。無ければボタンを押せない
- 候補から選んだURLは、その記事の候補内に限る（改ざん防止）
- 両方: X の失敗で止まり、IG の失敗では X を巻き戻さない。IG のみ: IG の失敗はそのまま失敗
- 1日の投稿数は X の枠なので、X に出したときだけ数える

## この日に確立した方針

1. **出す文そのものを、出す直前に検査する。** 途中の検査は前提にしない
2. **生成のルールと検証のルールは同時に直す**
3. **押しても何も起きないように見える状態を作らない。** 拒否は必ず見える形で
4. **本番と手元を混同しない。** 案内する前に origin/main を見る
